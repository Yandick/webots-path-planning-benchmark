# 提前让行的四个文献启发变体：对比实验报告

本报告在课设原有的「提前让行」（`CrossingGuard`，见 [coursework_path_planning_report.md](coursework_path_planning_report.md)）基础上，调研近年文献并实现了五个改进角度，在相同条件下与基线对照。数据与图表在 `results_extension/`，复现命令见文末。

## 动机与文献角度

原版让行在每个控制步沿当前路线向前估计约 3.5 s，用**纯匀速外推**预测来车，在"继续行驶"和"制动停车"两种假设中比较间距。文献中与之相关的四个改进方向：

1. **不确定性感知的自适应安全余量**（`astar_risk`）。激光拟合的速度估计有噪声，确定性余量应当随估计不确定度和预测时长放大。参照 Risk-Aware Adaptive Safety Margins（*MDPI Actuators*, 2026）与 ORCA-FLC（2025）。实现：`_Track` 在最小二乘拟合速度的同时求斜率标准误 `sigma_v`，冲突判定余量按 `0.5 × sigma_v × 预测时长` 放大。
2. **多假设来车预测**（`astar_hypo`）。匀速外推在小车中途停留、折返时是错的。实现：对每个轨迹同时评估"匀速"与"冻结在当前位置"两个假设取最坏情况，且不再跳过近似静止的轨迹。参照动态环境运动规划综述（arXiv:2606.02677, 2026）。
3. **时空 A\***（`astar_t`）。把"等待"从控制层的反应式刹车提升到规划层：在量化时间轴上做多维 A\*，等待是一个显式动作，输出带时间戳的路线路。参照无信号路口时空统一规划（2026）与 dynamic A\* 一脉的文献。实现见 [navigation/timed.py](../navigation/timed.py)，时间步 0.12 s，停车轨迹只按 5 s 停留窗口保守盖章（停留时长不可从激光预测，超时交由反应层）。
4. **互惠责任让行**（`astar_recip`），消融对照。ORCA 一族假设对方分摊避让责任。实现：所需间距乘以 (1 − 0.5)。本 benchmark 的小车按固定脚本行驶、**从不 reciprocate**，预期暴露假设失效的后果。
5. **PPO 学习让行决策**（`astar_ppo`）。用 PPO 策略替换规则阈值判断，把坐标系不变的轨迹特征（预测最小间隙、到达间隙时间、相对速度、估计不确定度、静止标志）映射到 {走, 慢速, 让行}。参照 Schulman et al. 2017（PPO）与"RL 高层决策 + 经典底层"的混合架构（IEEE JAS 2024）。**不需要预先收集数据**：PPO 是 on-policy，在仿真里边交互边学习；训练时小车时间表随机化 ±2 s（大于评估的 ±0.6 s），防止记住评估种子。安全由两层保证：物理间隙 shield（常速预测下表面间隙不足时强制让行，策略无权覆盖）与 unsafe-stop 规则无条件保留——**学习只调效率，经典层管安全下限**。

四个方法都以 A\* 为基座、复用同一个跟随器与观测层，在 [navigation/settings.py](../navigation/settings.py) 的 `EXTENSION_LABELS` / `GUARD_VARIANTS` / `TIMED_PLANNERS` 注册（含 `METHOD_REFERENCES` 文献出处），不影响网站管线要求的 8 个 canonical 方法。

## 实验设置

与基线完全同条件：三张公开地图 × 5 个种子 × 9 个方法（A\*、A\*+让行、RRT\*、RRT\*+让行 + 五个变体）共 135 次二维仿真，起终点、小车时间表、速度限制全部一致；机器人仍只从激光观测估计来车状态。PPO 变体的训练另用 ±2 s 宽随机化的小车时间表（不与评估种子重叠分布），评估时回到标准条件。

## 分角度结论

### 1. 风险自适应余量：中性，无差异

15/15 到达，用时、让行时间、最小间隙与原版让行几乎一致（四柱场地完全相同的轨迹）。原因：激光圆拟合在仿真里的速度估计质量很好，`sigma_v` 很小，风险项在 3.5 s 预测窗内只增加几厘米余量，不改变任何一次让行决策。这个角度本身合理（真实传感器噪声大时应有收益），但**在本实验条件下验证不到收益**。

### 2. 多假设预测：负收益（13/15，两起碰撞）

岔路迷宫种子 1、2 相撞，而让行时间从 2.9 s 涨到 15.4 s——更保守却更不安全。逐帧分析（`raw_runs.json.gz`）显示机制：冻结假设使机器人在**路口内部**就提前停车（它假设停着的小车可能永远不动）；当小车真的到来时，"停下"在小车的必经点上，`stop-vs-pass` 比较被迫选择"加速冲过"，而从静止起步的实际动力学落后于前向模型（假设立即 0.45 m/s），冲刺距离不够 → 5.19 s 类事故重演。原版匀速预测则让机器人在路口**外**的安全位置等待，永远不必做冲刺抉择。**教训：预测层的保守必须配合决策层的保守（停在冲突区之外），只在预测上加最坏假设反而把人放进更危险的决策点。**

### 3. 互惠让行：本条件下"没输的赌博"，不推荐

15/15 到达，平均还快 0.4 s（让行 2.4 s vs 2.9 s），最小间隙与原版完全相同。解释：本 benchmark 的几何余量充裕，间距阈值减半只让让行触发略晚，而实际通过间距由几何和小车驶离后的时机决定，没有收紧。但它安全性的论证被根本削弱——小车从不 reciprocate，15 次没撞上只是场景余量 absorbing 了假设错误，换一组更紧的时间表预期会撞。**负收益不在数据里，在论证里。**

### 4. 时空 A\*：预测稳定场景大幅占优，对抗性动态下可靠性不足

- 四柱场地 5/5，11.9–18.0 s（原版让行 14.1–15.7 s）；岔路迷宫 5/5，21.6–22.7 s（原版 34.7–37.7 s，**快 40%**），且多数种子几乎不停车等待（计划等待 0–0.7 s）——规划器主动选择时间窗穿过，而不是到路口再刹。
- U 形走廊 3/5：种子 3 超时、种子 4 在 23.4 s 相撞。根因：小车在走廊尽头**停留 14 s 后原路折返**，这是匀速/冻结预测都无法表达的意图；规划器把等待点选在小车折返时会扫过的走廊内部，反应式兜底（连续 3 次规划失败则退回纯反应让行 8 s）救回了岔路迷宫种子 4（43.4 s 到达），但救不了 U 形走廊里"等待点就在回扫走廊上"的死局。这是预测模型的表达能力问题，不是调参能解决的。

### 5. PPO 学习让行：标准条件下与规则版等价，宽分布下收敛到"信任 shield"

15/15 到达，平均 24.3 s，与规则版（24.4 s）统计上不可分，但分图看有结构性差异：U 形走廊 5/5 全部略快（21.1–22.2 s vs 21.6–22.8 s）——正好避开了时空规划撞车的场景；四柱场地多数种子略快、两个种子略慢（决策时机不同）。训练曲线（`results_extension/ppo_training_log.json`）揭示了一个诚实的结果：在 ±2 s 宽随机化的训练分布上，初始策略有 38% 的步在让行，收敛后让行率降到 ~1%——**规则阈值在宽分布下系统性地过度让行，学习策略把"该让才让"学到了**；但在标准评估分布上，过度让行的代价恰好被场景余量吸收，两者殊途同归。另一个发现：策略收敛到几乎"永远 GO"，真正的冲突全部由物理间隙 shield 拦截——在这个动作/状态规模上，学习到的决策退化为信任安全罩。这也让 benchmark 的 15/15 与 shield 的可靠性互为印证。

## 结论汇总

| 角度 | 相对 CrossingGuard 让行 | 一句话 |
| --- | --- | --- |
| 风险自适应余量 | 无差异 | 仿真估计太准，风险项不触发；真实噪声下或有收益 |
| 多假设预测 | **负收益** | 路口内停车 + 被迫冲刺，2 撞；保守预测须配合保守决策 |
| 互惠让行 | 条件性无差异 | 余量吃掉了假设错误；论证失效，不推荐 |
| 时空 A\* | 场景分裂 | 预测稳定时最快（最高 −40% 时间）；对抗性动态 13/15，需反应式兜底 |
| PPO 让行 | 标准条件下等价 | 规则版在宽分布下过度让行（38%→1%），标准分布下余量吸收差异；安全由 shield 兜底 |

## 复现

```bash
python evaluation/benchmark.py --workers 4 --output results_extension \
  --methods astar astar_yield rrt_star rrt_star_yield astar_risk astar_hypo astar_recip astar_t astar_ppo
python scripts/train_ppo.py   # 重训 PPO 让行策略（on-policy，无需数据集）
python -m unittest discover -s tests -v
```

数据文件：`results_extension/summary.csv`（逐次结果）、`raw_runs.json.gz`（含轨迹与让行事件）、`manifest.json`（方法注册与文献出处）、`trajectories.png`（种子 0 轨迹图）、`ppo_training_log.json`（PPO 训练曲线）。
